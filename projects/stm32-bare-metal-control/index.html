Bare-Metal Embedded Engineering on STM32F4 Nucleo

Developed a deterministic STM32F4 sensor-to-actuator platform and brought up a BNO085 IMU, validating the complete bare-metal toolchain, I²C communication, reset control, and data-ready interrupt path.

  • STM32F4
  • Bare Metal
  • BNO085
  • Real-Time Control

Configured and debugged the NUCLEO-F446RE in VS Code using STM32CubeMX, CMake/Ninja, the GNU ARM toolchain, and ST-LINK. A GPIO LED-blink test first confirmed that the complete build, flash, and debug workflow was operating correctly.

Explored the BNO085 over SPI1 in Mode 3 at approximately 1.31 MHz with dedicated chip-select, interrupt, and reset lines. Interrupt activity was visible, but valid SHTP packets were not received reliably, so the interface was moved to I²C for a stable bring-up.

Configured I2C1 at 100 kHz with PB8 as SCL, PB9 as SDA, PB5 as the falling-edge data-ready interrupt, and PA9 as sensor reset. PS0/PS1 select I²C mode and ADO selects the 0x4A device address.

HAL_I2C_IsDeviceReady() returned bno_found = 1 and bno_i2c_status = HAL_OK, confirming power, wiring, address selection, reset control, and bus communication. The BNO085 interrupt was observed low after startup and the STM32 EXTI counter incremented as expected.

Intermittent ST-LINK ‘Target no device found’ errors were eliminated by enabling Connect Under Reset. The next stage is implementing SHTP/SH-2 streaming for quaternion, roll/pitch/yaw, gyro, and other high-rate IMU reports.
